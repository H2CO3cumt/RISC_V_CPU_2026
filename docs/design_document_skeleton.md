## 第一部分 作品概述

### 1.1 功能与特性（380 字）

**要回答**：作品能干什么。

- 处理器：RV32I 全整数指令（算术、逻辑、移位、分支、跳转、load/store、fence、ecall/ebreak）。
- 流水线：IF/ID/EX/MEM/WB 五级；数据前递覆盖 EX 与 MEM 结果；Load-Use 插一拍停顿；分支与跳转解析后冲刷。
- 预测：16 项 BTB + 2-bit 饱和计数器，可编译期关断（On/Off 有 Before/After 数据）。
- 扩展：M 扩展 mul/mulh/mulhsu/mulhu/div/divu/rem/remu；rv32i 与 rv32im 两套镜像独立构建、独立留档。
- 异常：机器模式 CSR、mtvec/mepc/mcause/mtval/mstatus、MRET，三根通用中断输入。
- 存储：数据 RAM、UART（115200）、GPIO、MMIO 互连；行式突发适配（总线周期 48→30，claims §9）。
- 应用：八通道逻辑分析仪，五种模式，2048 样本 Raw，协议解析，仪器读数。

**图位**：无（模板"可加重要图"，本节不插图，把版面留给第一部分其它节）。

### 1.2 应用领域（380 字）

**要回答**：谁用、解决什么问题。

- 主场景：嵌入式板级信号观测与故障定位。现场 SPI/UART 异常时，静态读代码判断不了，需要看真实波形。
- 差异化：商用逻辑分析仪通道与协议固定；本作品用一片 FPGA 同时跑 CPU 和采集，采集源可选外部引脚或处理器内部观测点。
- 第二场景：RISC-V 微架构教学。单周期与五级流水对同一程序产生一致架构状态与提交序列，提交级 trace 可逐条比对。
- 边界：采集、触发、存储、回传全在 Core 外，换协议或加通道不动流水线。

**图位**：无。

### 1.3 主要技术特点（390 字）

**要回答**：技术上最值得写的几个点是什么。六条，每条不超过 65 字。

1. Core 与 SoC 严格解耦：只经统一取指事务、数据事务、提交事件对外连接。
2. 单周期做参考模型：同一程序两套实现比对架构状态与提交序列，差异定位到第一条不一致的提交。
3. 精确 Trap：异常在退休边界被接受，检测级只登记，mepc/mtval 由退休级给出。
4. 以实测决定取舍：I-Cache/D-Cache 功能正确但变慢（2,891,324 / 1,348,302 拍），按止损关闭；行式突发保留（claims §9）。
5. 自研工具自证：板载八通道采集直接观测自研处理器提交级行为，4,096 条记录与位流镜像逐条一致（claims §15）。
6. 数字可复核：每条指标有证据文件与位流 SHA-256。

**图位**：无。

## 第四部分 总结

### 4.1 可扩展之处（290 字）

- 存储层次：Cache 已实现但因后端仍是 BRAM 而无净收益，接上 DDR3 后端后可能翻盘（claims §9 的架构结论）。
- DDR3：S1 连通性已打通，尚未接入 CPU 存储路径（claims §12，按"未宣称"如实写）。
- 通道与协议：采集侧可扩到更多通道与协议，不影响流水线。
- 说明边界：AI/YOLO、HDMI、PCIe、千兆网不在本届范围。

### 4.2 心得体会（950 字）

- 建议四条线：①从单周期到五级流水的理解转变；②第一次被 halt 卡住后如何从第一个错误周期定位；③为什么用数据决定取舍（Cache 关掉是收益，不是失败）；④证据驱动的材料整理方式。
- 保留研发细节，不写空泛感想。
