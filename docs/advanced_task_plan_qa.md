# 赛题答疑驱动的进阶任务规划

> 2026-09-28。按用户要求，本规划从逻辑分析仪作品的赛题竞争力出发重新选择进阶方向，不沿用项目原先对 Cache、异常/中断的冻结取舍，并按“AI 负责设计、RTL、软件、测试、脚本与报告；人主要提供板卡连接和最终评审”组织任务。这里的 AI 指开发助手；**逻辑分析仪不需要部署 YOLO 或大语言模型**。本文是方案，不是已通过的工程 Gate；开始新增功能时，应同步修订 `AGENTS.md`、`docs/roadmap.md` 和 `docs/competition_scoring.md`，使开发记录与新目标一致。正确性、时序、Core/SoC 边界和可复现验证要求仍然适用。

## 1. 依据与答疑结论

依据：用户提供的四张赛题答疑截图、仓库保存的 2026 选题指南赛题页 `tmp/pdfs/riscv-topic-10.png` 与 `riscv-topic-11.png`，以及当前工程证据 `docs/progress.md`。截图中提到的“如上/如下问题”若未附原文，不推断额外细则。

| 答疑/赛题信息 | 对本作品的规划含义 |
|---|---|
| 综合考察应用能力、CPU 性能、资源与时序；没有公开的各项固定权重 | 先守住实际应用闭环和可靠演示，再用可复现的性能与高阶能力提高竞争力；不写“某项必得多少分” |
| 时序违例不接受；不同板卡的频率与资源不宜直接横比 | 所有结论绑定板卡、约束、位流、固件及工具版本；同板同配置做 Before/After，分别报告实际运行频率和时序扫描结果 |
| 板卡可自行选择，50k 级和 100k/200k mini 均可；指令/数据存储不限于 DRAM | 先用当前 MES50HP 做增量实验；只有资源、带宽或接口的实测证明必要时才比较换板。Cache 先证明存储瓶颈和后端可行性 |
| 可做硬件加速，可扩展指令集，可自选应用外设；不能用 ARM 硬核代替自研 RISC-V | “允许”不等于“需要”。本作品保持自研 RISC-V 控制的逻辑分析仪；不为了覆盖名目而增加 YOLO、通用 AI 或自定义指令 |
| CoreMark 官方源码不提供；运行须不少于 10 秒，可关闭不相关外设 | 固定可追溯的 CoreMark 源码、编译参数、镜像和 CRC；正式成绩写清被测配置与外设开关，不能把不同资源配置的指标混算 |
| 远程平台和初赛无实体板限制；现场演示与时序报告仍能区分作品 | 本项目已有 MES50HP，优先保留物理回环、串口和 ILA 原始证据，避免仅以仿真或视频宣称实板能力 |

赛题的高阶任务按**整组能力**描述：① 2 路组相联 I/D Cache 与突发传输；② 动态分支预测与完整异常/中断；③ RISC-V 控制的边缘 AI 加速系统。当前 16 项 BTB 只覆盖②的一部分，不能宣称整组完成。答疑明确说 AI 加速只是推荐方向，可以选择更合适的实际应用；本作品已选择逻辑分析仪，因此不把③列为当前实现目标，也不把逻辑分析仪冒称为 AI 高阶任务。

## 2. 当前可用起点与证据边界

- `docs/progress.md` 保存了五级 RV32I、BTB、UART/GPIO、逻辑分析仪、CoreMark 和 ILA 的通过记录。实体板记录为 50 MHz Score 45.051、80 MHz PLL Score 72.081；两次 `CoreMark/MHz ×1000 = 901`，CPI 约 1.5388/1.5387。85 MHz 是时序扫描通过点，**不是**85 MHz 实体计分。
- 这些数字对应当时的特定位流与镜像；当前工作区有多处未提交 RTL、发布材料和位流改动。重新测量前，不把历史成绩当成当前工作区的新成绩。
- 当前工作区包含多处未提交修改，且源码精读已有只读约定。新增设计应另用可追溯配置开发，不把未验证结果混入已演示的版本。

## 3. 推荐主线与顺序

我的排序是 **稳住逻辑分析仪与性能证据 → 消除已测 CPU 瓶颈 → 完成“BTB + 异常/中断”整组 → 以存储实验决定 Cache + burst → 深化逻辑分析仪的故障诊断与量化演示**。AI 开发助手能缩短编码与测试编写时间，但不会消除精确提交、真实存储后端、板级时序和实物演示的验证成本。已有 BTB 使高级控制逻辑的增量投入较小；Cache 的价值受存储后端限制。这是针对当前作品的工程判断，不是官方分值排序。

### 阶段 0：锁定可回退的参赛基线

| 顺序 | 工作 | 验收产物与继续条件 |
|---|---|---|
| A. 证据同源 | 核对最终 Core、固件、`.fdc`、PDS 报告、位流、板级日志、技术报告的版本和哈希；修正文档中的历史数字与当前数字混用 | 一张配置/哈希/指标对应表；全量最终 Regression PASS，50/80 MHz 的成绩与发布包可追溯 |
| B. 应用可靠性 | 固定 8 通道 Raw 逻辑分析仪的串口配置、触发、前后采样、UART/SPI 解析、VCD 和物理回环演示；准备断电、Reset、重连后的恢复流程 | 现场可改变输入再复现采集；连续采集和恢复日志 PASS；资源、时序和采样指标与同一版本对应 |
| C. 性能解释 | 用提交 trace、性能计数器与 PDS Fabric Debugger 对照 CoreMark 关键循环；解释乘法软件例程、分支 Flush、Load-Use 和总线等待各占多少 | 至少一个关键循环的原始波形、CPI 分解和瓶颈说明；仿真估计与实体数据明确分开 |
| D. BTB 证据 | 保留 Predictor Off/On 的同程序、同存储配置对比；检查预测正确后的控制重定向等已记录候选瓶颈 | Off/On 的 CRC、退休 trace、周期、CPI、LUT/FF、WNS、板级成绩成对记录；若修改 RTL，相关及最终 Regression 重新 PASS，Timing/应用演示不退步 |
| E. 材料与答辩 | 将赛题“基础任务、性能测评、应用场景、高阶任务”逐项映射到证据，清楚写出未实现项 | 评委能从报告找到每项声明的原始测试；答辩中可准确区分 BTB 子项、完整高阶组、PDS ILA 与作品逻辑分析仪 |

**阶段出口：** `competition_final` 或同等可回退版本的 RTL、软件、PDS、位流、报告和演示一一对应。阶段 0 不必等整个新路线结束才写材料；每个后续阶段都从这份基线比较。

### 阶段 1：先拿可复现的 CPU 性能增益

优先检查已有记录指出的“跳转预测正确仍重定向”路径，先修正 JAL/JALR 的预测训练语义，再测可避免的 Flush；若证据显示瓶颈已变化，就重新做 CPI 分解，不机械照旧结论改 RTL。一次只改一个原因，保留 Predictor Off/On。独立分支/跳转测试、提交级 trace、CoreMark CRC、应用回归、PDS Timing 和实体运行全部通过，且 CoreMark/MHz 或 CPI 有稳定净收益，才进入候选版本。历史文档中的约 7.7% 周期空间是估计上界，不是承诺成绩。

### 阶段 2：完成官方“动态预测 + 异常/中断”组

#### H1：精确异常/中断

已有 BTB 可复用，但精确异常会触及 IF～WB 的有效位、提交、副作用和已发事务，不能按“加几个 CSR”估算工作量。

1. 先冻结机器模式支持矩阵：CSR 指令与相关寄存器、`ECALL/EBREAK/MRET`、非法指令、取指/Load/Store 的未对齐与访问错误、外部/定时器中断、屏蔽、优先级、入口和返回语义；写明所依赖的特权规范版本及明确不支持的范围。
2. 用逐周期图确定较老指令完成、较年轻指令取消、Trap 与 BTB 误预测/Load-Use/总线等待/Reset 冲突时的优先级。中断源与定时器放在 SoC，Core 只接通用中断线。
3. 独立 CSR/Trap 测试、随机背压、错误路径零 MMIO 副作用、参考事件检查器、裸机中断程序、完整 CoreMark 与逻辑分析仪回归，最后再上 MES50HP 测时序和实板响应。

**通过条件：** 支持矩阵逐项 PASS，精确提交与副作用正确，原功能、CoreMark、Timing 和实板演示不退步。只有预测和异常/中断两部分都达到定义的覆盖范围，才报告完成该高阶组；若只能完成一部分，按子能力如实报告。

### 阶段 3：2 路 I/D Cache + 真实 burst

1. 先测当前取指/数据事务的延迟与瓶颈，并验证拟用后端的控制器、时钟、初始化、随机/连续读写、突发长度、带宽、资源与时序。答疑允许片上 RAM，因此 **DDR 不是形式上的必选项**；但只有普通 BRAM 接口、没有真实突发收益时，不能宣称已完成“突发传输优化”。
2. 可行性通过后，分别设计 2 路 I-Cache/D-Cache，定义组数、行长、替换、写策略、miss refill、字节写、错误、复位以及所有 MMIO 绕行；保持 `docs/interfaces.md` 的 Core/SoC 事务边界。若改变软件可见的取指一致性，必须写清 `FENCE.I` 等约定并验证。
3. 以同一后端、同一程序比较 Cache Off/On 的 miss、总线事务、CoreMark/MHz、Fmax 和资源；覆盖冲突 miss、Store→Load、背压、Reset 和 MMIO 仅一次副作用。

**止损条件：** 后端不可用、突发无可测收益、Timing 违例或 CPU/应用回归退化，就停在原型/研究结论，不并入主配置，也不宣称完成整组。若在 MES50HP 上资源紧张，再以同一功能和测试矩阵评估换板；不能用换板后的绝对频率与旧板直接比较优化收益。

### 阶段 4：深化逻辑分析仪的应用价值

围绕现有采集系统做可重复的故障定位演示：例如给 UART/SPI 信号注入可控的错误、间歇抖动或时序偏移，让 RISC-V 软件配置触发条件，采集原始波形并由上位机解析、标注故障位置。量化触发延迟、采样深度、可检测的错误类型、定位准确率、上传耗时和连续运行稳定性。新增分析功能先放在 Core 外的软件或 MMIO 外设中，不破坏已有采集闭环。

**通过条件：** 输入故障可控、采集结果可复现、故障位置能与注入真值自动比较，资源和时序不退步；现场能改变故障条件并重新演示。它是应用创新与实际功能证据，**不宣称完成边缘 AI 高阶组**。只有作品方向改为模型推理应用时，才另立 AI 加速计划；本规划不要求部署 YOLO 或大模型。

## 5. 统一实验与宣称规则

每一轮只改变一个设计变量，记录基线与改后版本的 RTL/固件/约束/位流哈希、板卡、工具、频率、CoreMark 迭代和 CRC、持续时间、LUT/FF/BRAM、WNS/WHS、CPI 与应用表现。`CoreMark/MHz` 用实际运行频率归一化；`CoreMark/LUT` 必须注明分母是 Core、SoC 还是整机的哪一份实现，避免与另一配置混用。仿真、综合估算、时序扫描和实体板实测分列。时序违例、功能 Regression FAIL、错误路径出现副作用或板上不可重复，均不得作为完成结果。

## 6. 交给 AI 执行的任务包

不要给 AI 一条“把三个高阶任务全部做完”的总指令。每个任务包只有一个可审查目标；AI 可完整编写 RTL，但要提交设计说明、独立测试和可复现命令。下面的“并行”只指只读调查或独立原型，不能同时改同一份 Core。

**Verilog 可读性要求：** 一行只写一条完整的声明、赋值或控制语句；不要把多个赋值、多个条件分支或一串操作压在同一行。`if/else`、`case`、状态转移和握手逻辑按层级换行、缩进，让人能顺着周期行为读下去。对状态编码、状态转移、`valid/ready`、Stall、Flush、Forwarding、访存副作用及提交时机写必要的**中文注释**，说明“为什么这样处理”和“在哪一拍生效”；不用英文注释，也不写“判断条件”“更新寄存器”一类只复述代码的套话。保持已有模块的命名与排版习惯，不为统一风格重排无关 RTL。代码审查把这一条列为验收项。

| 包 | AI 直接交付 | 自动验收 / 阻断条件 |
|---|---|---|
| A0 基线审计 | 盘点未提交改动、源文件/位流/报告哈希、当前 Regression、板级成绩来源，建立只读基线清单 | 关键证据能对应同一配置；发现矛盾先修正文档与证据，不开始高阶 RTL |
| A1 跳转性能 | 定位首个错误/浪费周期与信号，给出逐周期图，最小修改 BTB/Redirect，并提供 Off/On 对比脚本 | 指令/跳转 TB、退休 trace、官方 CRC、最终 Regression、PDS Timing PASS；有可重复的 CPI 或 CoreMark/MHz 净收益才保留 |
| A2 Trap 契约 | 列 CSR、异常原因、中断源、优先级、Trap/返回周期和现有总线取消语义；写 TB 验收矩阵 | 契约可覆盖取指、Load/Store、分支误预测、Stall、Reset、MMIO 副作用；未定义行为不得进入 A3 |
| A3 精确异常 | 在 A2 契约下实现 CSR/Trap/`MRET`，先做同步异常，再做 SoC 外部/定时器中断；提供独立事件判定器与裸机程序 | 每个子集单独 PASS；旧单周期模型未支持 Trap 时不能拿它冒充此功能的参考模型；完整旧回归与时序均 PASS |
| A4 存储可行性 | 测当前存储延迟，完成拟用后端最小 burst 读写演示和资源/时序报告；可与 A2 的只读规格工作并行 | 没有真实可用后端、可测 burst 效率或足够资源，就停止 Cache 整组实现 |
| A5 Cache | A4 通过后，先 I-Cache 再 D-Cache，最后真实行填充/写回或写穿 burst；每步保留 Off 开关 | 独立 Cache TB、随机背压、MMIO 绕行、Store→Load、Reset、CoreMark 与应用回归、PDS Timing/资源/板级收益均 PASS |
| A6 故障诊断演示 | 在现有逻辑分析仪上建立可控故障注入、Raw/VCD/解析结果与真值自动比较，形成量化报告和现场步骤 | 采集、定位、复现与回归 PASS；采样资源和时序不退步；不标称 AI 高阶任务 |
| A7 发布 | 选择通过**所选功能全部验收**的唯一主版本，重跑全量 Regression、PDS、CoreMark 和实物演示，更新报告、视频与哈希 | 任何新增功能导致时序违例、正确性倒退或现场不可重复，就退回最近的通过版本；未选或未通过的高阶组不得写成已完成 |

### 每个 AI 任务包的回交格式

1. **改了什么、为什么**：设计取舍、接口/状态更新和首个受影响周期；列出全部文件与原有未提交改动如何保留。
2. **怎么证明**：实际命令与 PASS/FAIL、首个失败点、未覆盖项；功能必须有自动判定，不能仅看波形。逐文件检查新增 Verilog 是否遵守“一行一条语句”和关键时序中文注释要求。
3. **值不值得保留**：同板、同程序、同约束的 Before/After；分开写 RTL 仿真、综合估算、时序扫描和实板测量。
4. **能否进入下一包**：逐项对照该包阻断条件；如果失败，保留日志和原型结论，主版本回到上一个通过点。

**总验收线：** 每个任务包有独立可回退版本；基础 RV32I、CoreMark、逻辑分析仪和现场演示不因高阶功能倒退。开始新增 RTL 前，把新的 Gate 与验收矩阵写进项目契约。时间紧张时优先完成 A0～A3、A6 和 A7；A4 可及早做只读可行性评估，A5 只在 A4 通过后投入。
