# 面向国赛的进阶任务执行清单

> 2026-09-23 重写。用户已明确要求按赛题和工程竞争力重新规划，**不沿用旧文档对 Cache、异常/中断、AI 等功能的范围冻结决定**。本清单是新的实施建议；旧 `AGENTS.md`、`docs/roadmap.md`、`docs/competition_scoring.md` 与它存在范围冲突，执行新功能前应同步改写这些项目契约，避免后续 AI 误判任务范围。保留已有成果和未提交改动，不覆盖当前发布包。

## 一句话判断

当前工程已有 RV32I 五级流水、BTB、UART/GPIO、官方 CoreMark 实测、80 MHz 实板运行、ILA 波形和逻辑分析仪应用闭环，具备竞争基础。**最有胜算的路线是：可靠演示 + 可复现性能提升 + 完整做成一组官方高阶任务。** 首选补齐“BTB + 精确异常/中断”；再尝试双路 I/D Cache 与真实 burst；AI 加速先做资源/设备可行性核算，具备完整模型和外设闭环条件才投入实现。任何路线都不能保证晋级，最终由当届评审与其他作品决定。

依据：仓库保存的 2026 紫光同创 RISC-V CPU 赛题原页 `tmp/pdfs/riscv-topic-10.png`、`tmp/pdfs/riscv-topic-11.png`；[大赛评审依据](https://fpga2024.fpgachina.cn/question)关注完成度、难度/工作量、创新/适用、平台利用、综合指标、报告、现场演示与答辩。官方没有给出本题各高阶项固定权重，不以“做了某项必晋级”排序。

## 第一梯队：直接提高晋级竞争力

### P0. 先把可参赛基线固定下来（AI 可主做；实板需人配合）

- [ ] 盘点工作区、交付包、固件、位流、报告和原始测试日志，建立同版本哈希表；处理报告中的旧成绩和“仿真/估算/实板”混用。
- [ ] 跑完整 RV32I、单周期/流水线退休 trace、随机背压、UART/GPIO、逻辑分析仪、CoreMark 和 PDS 时序回归；记录首个失败点。
- [ ] 在当前正式位流上重复 CoreMark、ILA 和逻辑分析仪演示，做断电/复位/重新下载恢复；保存视频或原始日志。
- [ ] 冻结可回退的基线配置和统一的演示脚本。**完成条件：** 代码、固件、PDS 报告、位流、实测成绩与参赛材料一一对应，全套测试 PASS。

### P1. 性能优化：先拿到实测收益（AI 可实现和仿真；实板需人配合）

- [ ] 优先修正已定位的跳转浪费：`rtl/pipeline_cpu.v` 对 `idex_jump` 无条件 redirect；先使 JAL/JALR 的 BTB 训练恒 taken，再只在预测错误时重取。每一步单独测量，不把预计 7.7% 周期空间写成已实现收益。
- [ ] 用当前 ILA/性能计数器重新量化 load-use、数据事务阻塞和分支损失。只有当改动能减少**已测的**等待周期时，再做数据访问与取指重叠、时序关键路径等下一轮优化。
- [ ] 每轮比较 CoreMark/MHz、满足约束的频率、CoreMark/LUT、CPI、WNS、LUT/FF/DRM，连同预测关闭配置和逻辑分析仪配置一起回归。**完成条件：** 官方 CRC、完整回归、板级稳定性不退步，至少一项主要指标有可复现净收益；否则回退。

### P2. 把“动态预测 + 异常/中断”做成完整高阶能力（首选新增高阶任务）

这项最贴近现有 BTB：新增工作虽会触碰流水线控制，但不要求重建外部存储体系或更换应用。AI 可承担规范梳理、RTL、独立 TB、软件与回归；用户要审核架构取舍并做实板演示。

- [ ] **P2a 规格先行：** 选定 RISC-V 特权规范版本，列出 Machine-mode 支持矩阵：CSR 读改写、`mstatus/mie/mip/mtvec/mepc/mcause/mtval`、`MRET`、非法指令、`ECALL/EBREAK`、取指/Load/Store 访问错误与未对齐、外部/定时器中断、优先级和向量/直接入口。明确不支持的特权级与行为，避免“完整”口号没有边界。
- [ ] **P2b 精确 Trap 数据通路：** 以退休顺序为准，保证较老指令完成、较年轻指令取消；处理已发出的取指/数据事务、BTB 误预测、等待、Flush 同时发生时的优先级。异常原因和 `mepc`/`mtval` 可追溯到首个错误周期。
- [ ] **P2c Core/SoC 中断链：** Core 只接受通用中断信号；定时器、中断源与聚合器留在 SoC。写可运行的中断服务程序，演示屏蔽、响应、返回和再次触发。
- [ ] **P2d 验收：** 独立 CSR/Trap TB、异步中断注入、随机背压、Reset、错误路径零 MMIO 副作用、嵌套/非嵌套测试；建立支持 Trap 的参考模型或独立事件判定器，不能用现有“非法指令直接跳过”的单周期模型判错。完整 RV32I/GCC/CoreMark/应用回归与 PDS Timing PASS，实板上展示异常处理和周期性中断。

**宣称边界：** P2a～P2d 均通过后，才可说实现了赛题的“动态预测以及完整异常/中断”高阶组；具体“完整”必须附覆盖表。只加一个中断输入或只支持 `ECALL` 不够。

## 第二梯队：资源与存储路径允许时，完成双路 Cache + burst

赛题要的是**指令 Cache + 数据 Cache + 2 路组相联 + 突发传输优化**这一整组。当前片上 BRAM 请求响应每端口最多一笔未完成事务，单纯在 BRAM 前加 Cache 可能既不改善 CoreMark，也无法证明“总线 burst 优化”。MES50HP 手册列有 DDR3 管脚，但当前仓库尚无已验证 DDR3 控制链。因此先做真实存储后端可行性，再决定是否投入完整实现。

- [ ] **P3a 可行性闸门：** 核实板上 DDR3/QSPI 的器件、控制器/IP、PDS 许可证、管脚、时钟、PHY、初始化和最小读写 demo；测随机/连续访问延迟、吞吐与资源。若只有无 burst 的 BRAM 路径，仍可做 Cache 原型，但不宣称完成官方整组。
- [ ] **P3b I/D Cache：** Core 外分别实现 2 路组相联 I-Cache、D-Cache；定容量、行长、替换、写穿/写回、脏行、字节写、miss refill、错误、复位、地址别名与所有 MMIO 绕行。保持 CPU 端现有统一事务语义。
- [ ] **P3c burst 后端：** 以真实后端完成整行突发读/写，记录突发长度、有效带宽和总线周期；补齐数据一致性及 `FENCE`/`FENCE.I` 软件约定，避免 Cache 与旧 no-op 行为冲突。
- [ ] **P3d 验收：** 冲突/容量 miss、store→load、自修改代码、未对齐、异常、背压、复位和 MMIO 一次副作用全部 PASS；CoreMark 与应用 Off/On 在相同后端比较，同时给资源、时序、实板稳定性。**只有真实 burst 和 I/D 双 Cache 全通过，才宣称完整存储高阶任务。**

P3a 失败时停下 P3b～P3d，将 AI 时间投入 P1/P2 与应用演示；这不是简单的“以后再说”，而是有量化止损条件。

## 第三梯队：AI 加速先算清楚，再决定是否做整套

官方 AI 项要求边缘 AI 加速系统、YOLO 或轻量大模型，以及传感器/显示设备和实际功能。板卡虽有 84 APM 与 DDR3 接口资料，但**没有现成的模型、摄像头/传感器、存储控制器和推理演示链**；纯软件识别或单个乘加器无法算完成。因此这项是高投入、高风险的冲刺项，不宜挤掉 P0～P2。

- [ ] **P4a 48 小时可行性核算：** 明确一个真实任务、输入/输出设备、模型版本与精度，计算权重/激活容量、MAC 数、带宽、期望帧率/延迟、LUT/APM/BRAM 预算，并验证传感器与板级接线可用。达不到目标则停止整套 AI 实现。
- [ ] **P4b 若 P4a 通过：** AI 完成量化与黄金模型、外部 MMIO 加速器、驱动、数据搬运、端到端推理测试；优先利用已有逻辑分析仪采集的数据做故障诊断辅助演示，但这只能算应用创新，不能替代赛题明确的 YOLO/大模型要求。
- [ ] **P4c 实板闭环：** 实际设备输入 → FPGA 加速 → RISC-V 控制/读取 → 设备或上位机输出；测准确率、端到端时延、吞吐、功耗（有仪表时）、资源和时序。没有完整模型和实体链路，只以“AI 原型”呈现。

## 按时间推进：一轮只动一个瓶颈

| 阶段 | 主要工作 | 继续/止损条件 |
|---|---|---|
| 第 1 周 | P0 冻结基线；P1 跳转优化；同时完成 P2a、P3a、P4a 的**只读规格与资源核算** | 回归和演示稳定；P1 有实测收益；P3/P4 有真实后端/设备证据 |
| 第 2～3 周 | 主力完成 P2b～P2d；若 P3a 通过，独立配置推进 P3b～P3c | P2 精确 Trap 与现有程序均 PASS；P3 不能拖累 P2 |
| 第 4 周及之后 | P3d 资源/性能实测；只有 P4a 强通过且 P0～P2 稳定时做 P4b～P4c；集中准备现场演示和答辩 | 新增功能失败、退化或板上不可重复时回退到最后稳定版本 |

这是工作量安排，**不是官方赛程**。具体截止日期以实际赛程为准。晋级目标应优先确保一个稳定、能解释性能数据、能现场演示的完整系统，然后用 P2/P3 增加赛题高阶覆盖。

## 交给 AI 的统一任务指令

每次从上述清单取**一个编号**给 AI，要求它先检查当前未提交改动和基线哈希，列出设计与验证矩阵，再做最小实现。回交必须包含：修改文件、首个错误周期/信号、实际运行命令、PASS/FAIL、实板与仿真的证据边界、Before/After、剩余风险和是否达到该编号的完成条件。Core 改动要重跑相关 Regression；性能优化没有净收益或时序/功能退步就回退该轮。所有设备专用逻辑继续放在 Core 外，这是本工程现有接口与验证体系的技术前提，而非旧范围冻结。
